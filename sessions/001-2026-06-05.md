## Canonical puzzle schema (lock this as TypeScript next)

```typescript
type Puzzle = {
  id: string                    // "puzzle-NNN" (zero-padded)
  date: string                  // "YYYY-MM-DD"
  title: string
  baseProblem: {
    statement: string
    example: {
      input: unknown            // shape is per-puzzle (object, string, number, array)
      output: unknown           // same — renderer must adapt
    }
  }
  rounds: Round[]               // exactly 5, in the order below
}

type Round = {
  id: number                    // 1..5
  type: "principle" | "approach" | "complexity" | "ambiguity" | "edgeCase"
  timeLimitSeconds: number      // canonical: 20, 25, 20, 30, 25 by round
  question: string
  options: string[]             // exactly 4
  correctIndex: number          // 0..3
  explanation: string
}
```

**Invariants enforced by the validator (`node -e` one-liner in session 001 transcript):**
- `rounds.length === 5`
- `rounds[i].type === ["principle","approach","complexity","ambiguity","edgeCase"][i]`
- `options.length === 4`, `correctIndex` in `[0,3]`

**Stylistic conventions (already applied across all 10):**
- Inline literal input values in options/explanations use escaped double quotes: `\"abba\"`, `[\"eat\", \"tea\"]`
- Dialogue and word emphasis use single quotes: `'yes'`, `'Is an empty string a palindrome?'`
