## Surprises / improvisation

1. **`create-next-app .` refuses a non-empty dir** (our `.claude`, `CLAUDE.md`,
   `db`, `puzzles`, `sessions` aren't on its ignore-allowlist). Workaround
   (user-approved): scaffold into a temp subdir, then move only the generated
   files up — existing content never moved. Note: the temp dir **can't start
   with a dot** (npm naming rule), so it was `scaffold-tmp`, not `.scaffold-tmp`.
   The template also dropped its own stub `CLAUDE.md`/`AGENTS.md` in the temp
   dir; those were intentionally **not** moved up (would have clobbered ours).
2. **Version-pin correction (user-approved deviation from the original plan
   table).** Raw `dist-tags.latest` gave `typescript 6.0.3` and
   `@types/node 25.9.1` — but TS 6 is an unverified-with-Next16 major and
   `@types/node` 25 describes Node 25 APIs while we run Node 20. Pinned the
   latest **within the template's majors** instead: `typescript 5.9.3`,
   `@types/node 20.19.41`. `react`/`react-dom` kept at the template's exact
   `19.2.4`. This matches CLAUDE.md's "most stable verified builds."
3. **`npm ci` needs a lockfile first.** The plan literally said
   `rm -rf node_modules package-lock.json && npm ci`, which can't work (no lock).
   Did `npm install` once (no package arg — allowed; the ban is on
   `npm install <pkg>`) to generate the lock against the exact pins, then
   `rm -rf node_modules && npm ci` to prove reproducibility.
4. **`noUncheckedIndexedAccess` closure narrowing.** In `Player.tsx`, the
   `if (!round) return null` guard does **not** carry into the nested
   `choose`/`optionClass` closures — `round.correctIndex` tripped
   "possibly undefined" at build. Fixed by hoisting `const correctIndex =
   round.correctIndex` after the guard and using that local in both closures.
   (Surfaced only at `next build`'s TS pass, not at first compile.)
5. **Audit warning, left as-is (flagged per CLAUDE.md).** 2 moderate advisories,
   both `postcss <8.5.10` (XSS via untrusted CSS stringify, GHSA-qx2v-qp2m-jg93)
   pulled in **transitively inside `next@16.2.7`'s own deps**. npm's only "fix"
   is downgrading next to v9 (absurd). Not controllable via our pins, not
   exploitable here (we author all CSS), already on latest stable next. Did
   **not** run `npm audit fix --force`.
6. **`Topic` column is a placeholder** = the puzzle title (the plan's
   "from title for now"). Real topic tags are a deferred schema decision
   (session 001 open question).
