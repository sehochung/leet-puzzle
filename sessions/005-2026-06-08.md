## Schema audit findings (the brief's premise was inverted)

The brief assumed options carried at most a single-language `codeFragment`, that **distractors
had no code**, and that 9 puzzles were stuck "canonical-only" pending fragment authoring. The
repo is the opposite:

- **`Option` already has bilingual `fragments: { python, java }` on *every* option** (canonical
  *and* all 3 distractors). `lib/parse-puzzle.ts` and `scripts/validate-puzzles.mjs` already
  *require* them non-empty in both languages. (Session 004 had flagged this: *"generous mode is
  already unblocked … needs no schema change."*)
- **All 10 puzzles already carry full, high-quality distractor fragments** (verified 001/002/003).
  The 15 fragments Phase 2 wanted authored **already existed** — and are better than the brief's
  single-language suggestions (e.g. round-4 `groups[key] = groups.get(key, []) + [s]` is a
  complexity trap, not a crash).
- The app is **bilingual** (Python/Java `LangToggle` + global `language` state). A single
  `codeFragment: string` would have **broken the toggle**.
- Puzzles 002/003 already have **multi-line** fragments, so the brief's "one-line fragment"
  invariant was already violated — the panel had to split on `\n` regardless.

**Decisions taken (user-approved):**
1. **No `codeFragment` field.** Everything reads `options[pick].fragments[language]`.
2. **`constructionMode: "diff" | "canonical-only"`** added as the brief asked, *derived* in the
   parser. It is **always `"diff"`** for current data (the parser forbids empty fragments), so
   the canonical-only branch is unreachable today — but `ConstructedCode` + `buildConstructedCode`
   + the session-004 end screen are **kept** as a real fallback for any future puzzle authored
   without distractor fragments (honors "DO NOT remove that path").
3. **Roll the diff UI out to all 10 puzzles** (since the data exists). 002–010 keep their existing
   standalone questions; only puzzle-001 got chained questions this session.
4. **Per-line rationale toggle shipped now** (the brief marked it optional/deferrable).

## The 5 rewritten puzzle-001 questions (chained narrative)

1. **state:** "Before scanning the strings, what container do you need so anagrams end up grouped together?"
2. **iterate:** "You have an empty hashmap. How do you process the input to populate it?"
3. **transform:** "For each string you process, you need a key that's identical for anagrams and different for non-anagrams — what's the right canonical form?"
4. **update:** "With a key derived from each string, how do you record this string under its key?"
5. **output:** "Your hashmap now groups strings by canonical key. What do you return?"

Each opening clause states what the player has already built (visible in the panel above); the
rest describes the slot to fill.

## The 15 distractor fragments — `ast.parse` + runtime (puzzle-001, Python)

Composed each option into the scaffold (canonical elsewhere), `ast.parse`d it, then ran
`solve(example)`. **All 20 options parse OK.** Example input
`["eat","tea","tan","ate","nat","bat"]`; canonical output `[["eat","tea","ate"],["tan","nat"],["bat"]]`.

| Round | Option | parse | runtime on the example |
|---|---|---|---|
| 1 state | ✓ `groups = {}` | ok | correct |
| | `groups = []` | ok | **AttributeError** (list has no `.setdefault`) |
| | `seen = set()` | ok | **NameError** (`groups` never defined) |
| | `counts = {}` | ok | **NameError** (`groups` never defined) |
| 2 iterate | `for i in range(len(strings)):` | ok | **NameError** (body uses `s`) |
| | ✓ `for s in strings:` | ok | correct |
| | `for s in sorted(strings):` | ok | correct groups, different order† |
| | `for s in reversed(strings):` | ok | correct groups, reversed order† |
| 3 transform | `key = len(s)` | ok | one giant group (all length 3) |
| | `key = frozenset(s)` | ok | **coincidentally correct on this input**, wrong in general‡ |
| | ✓ `key = "".join(sorted(s))` | ok | correct |
| | `key = (s[0], s[-1])` | ok | every string its own group |
| 4 update | `groups[key] = groups.get(key, []) + [s]` | ok | **correct but O(n²)** (rebuilds bucket) |
| | ✓ `groups.setdefault(key, []).append(s)` | ok | correct |
| | `groups[key] = s` | ok | keeps only the last string per key |
| | `groups.append(key)` | ok | **AttributeError** (dict has no `.append`) |
| 5 output | ✓ `list(groups.values())` | ok | correct |
| | `groups` | ok | returns the dict (wrong type) |
| | `list(groups.keys())` | ok | returns canonical keys, not groups |
| | `[s for g in groups.values() for s in g]` | ok | flattens the groups away |

† Order-only difference; the test harness compares order-insensitively, so these *pass* in
Python. They remain pedagogically wrong (extra `n log n`; the Java `TreeSet` form silently drops
duplicate strings). ‡ `frozenset` ignores character multiplicity (`aab` vs `ab`), so it's wrong
in general even though it matches this particular example.

**This is the project's "distractors are pedagogy, not gated" rule in action:** several distractors
don't crash — they're correct-on-the-example or correct-but-slow — so the teaching lives in the
*rationale and general-case reasoning*, which is exactly why we never execute distractors.

## Surprises

1. **The brief described a world two sessions out of date.** Distractor fragments, bilingual data,
   and multi-line fragments all already existed; the "author 15 fragments / 9 canonical-only
   puzzles" plan had nothing to do. The schema audit (run in plan mode, as the brief required)
   caught it, and the user chose to roll the diff UI to all 10 rather than just puzzle-001.
2. **Some puzzle-001 distractors don't fail at runtime** (order-only iterate variants; `frozenset`
   matches this example). Good reinforcement that distractor validation must stay a typo-catcher
   only — runtime/type/wrong-output (and even "passes the example") flow through as pedagogy.
3. **The scaffold doubles as the layout source of truth.** Rendering the marker's scaffold line
   (not the bare fragment) gave correct indentation *and* the `return …;` wrapper for free, and
   made multi-line fragments and the output stage fall out without any special-casing.
4. **Headless Edge inherited the OS dark theme**, so the "dark mode" screenshots came for free —
   no `prefers-color-scheme` emulation flag needed.
