## Partial execution — the approach actually used (no fallback needed)

- `lib/partial-code.ts` — `buildPartialRunnableCode`: canonical fragments for filled rounds +
  **slot-aware stubs** (state/transform/update → `pass`; iterate → `for _ in []:` so deeper
  stubs don't IndentationError; output → `None` inside `return {{output}}`). Rounds lock in
  order, so unfilled slots are always a suffix and every prefix parses.
- `lib/run-python.ts` `runTraced` + `TRACE_HARNESS` — **one `sys.settrace` hook supplies all
  three sections**: line events → TRACE (source line + locals-diff attributed to the line that
  caused it, 200-step recording cap), final locals snapshot → STATE, return event → OUTPUT.
  The preamble's module-scope STATE idea was unworkable (`return` in every scaffold body is a
  module-scope SyntaxError) — frame tracing replaced it.
- **The tracer doubles as the infinite-loop guard** (8k step budget → `stopped:
  "step-budget"`): puzzles 003/004/007/008 genuinely loop forever while their while-loop's
  update round is stubbed, and Pyodide runs on the main thread.
- The stubbed `return None` line number is passed to the harness so a stub return reads as
  "(not yet returned)" while REAL early returns (002's in-loop return) show their value.
- **Verified:** all 10 puzzles × 6 prefixes run clean under local Python (zero errors;
  step-budget exactly where predicted), and the identical harness was confirmed under real
  Pyodide WASM in headless Edge (boot ~1.1 s; settrace + step budget both work in WASM).

## Surprises

1. **The 006 end-run never ran the user's code.** `buildConstructedCode` always composed
   canonical; the "build blind then run YOUR code" payoff was an illusion. Corrective mode
   absorbed the bug as intended behavior — but it's a lesson in verifying the actual data
   path, not the demo rig.
2. **The preamble's module-scope STATE recipe couldn't work** (`return` at module scope) —
   settrace-on-the-frame turned out simpler AND solved the infinite-loop hazard the preamble
   missed (4 of 10 puzzles hang with a stubbed update round).
3. **Several authored traps are invisible on the first test input** (frozenset, store-first,
   bisect_right, set(t) — all "coincidentally correct" there). Bridge traces for those pair
   the first input with a minimal probe that exposes the flaw — pedagogy needed both.
4. **The spec's 5-color wayfinding survived contact with the user for one message.**
5. `while`-stub traces would have frozen the tab silently if the step budget had been an
   afterthought — it fell out of settrace for free.
