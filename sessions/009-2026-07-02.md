## Schema changes

- `Puzzle.lightning?: LightningQuestion[]` — optional (absent parses as `[]`);
  `{ kind, question, options[4] (plain strings), correctIndex, explanation }`.
  Parser: `parseLightningArray` in `lib/parse-puzzle.ts`; validator mirror in
  `scripts/validate-puzzles.mjs` (PASS line now prints the lightning count).
- **New design schema** (`lib/design.ts` + `lib/parse-design.ts` + `lib/design-puzzles.ts`):
  `DesignPuzzle { id /^design-\d{3}$/, title, brief, requirements[], rounds[5] (stage order
  requirements|api|data|scale|tradeoff, 4 options of {conceptLabel, rationale}), diagram
  {nodes, edges}, capacity[] }`. Nodes carry SVG geometry (720×340 viewBox) +
  `appearsAtRound` 0..5; edges are validated to reference real node ids. Loader has the same
  validate-id-before-fs posture as `lib/puzzles.ts`. Validator prints
  `PASS design-001.json (design, 8 nodes / 7 edges)`.
- Design files live in `/puzzles/design-NNN.json` — the code-puzzle loader's
  `^puzzle-\d{3}\.json$` filter means no collision.

## Progression / XP model (lib/progress.ts)

- `computeXp = firstPickScore*20 + testsPassed*5 + lightningScore*15` (max 165/puzzle,
  100/design). `recordCompletion(puzzleId, summary, isDaily)` → `Award` (xpGained, rank,
  next, progress, rankedUp, streak, streakExtended).
- **Called twice per code run** (once at results, once after lightning): safe because XP is
  the delta over `bestXp`; the Player accumulates `xpGained` across the two for display.
- Streak: `lastDailyDay` vs `dayIndex()` (yesterday → +1, else reset to 1); idempotent per
  day; `dailyDays[]` drives the heatmap. `streakAlive()` = last daily today/yesterday.
- localStorage key `iit-progress-v1`, versioned, SSR-safe, never throws.

## Gotcha found & fixed: answer-position clustering (`8e7aadb`)

First authoring pass put the correct option at index 0 for almost every lightning question
and every design round — players would learn "pick the first one". A one-shot script moved
each correct option to a varied deterministic slot (lightning targets derived from puzzle
number; design targets hand-picked). **Standing authoring rule saved to memory:** whenever
authoring option sets, distribute `correctIndex` across positions before committing.
